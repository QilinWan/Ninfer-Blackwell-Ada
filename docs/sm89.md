# NInfer on Ada (`sm_89`)
> 中文镜像见 [sm89.zh-CN.md](sm89.zh-CN.md)；本页为准。

This document is the authority for what this repository changes relative to
[Neroued/ninfer](https://github.com/Neroued/ninfer), why each change is required by the architecture,
and how a claim here can be checked. Product behaviour — CLI, serving protocol, weight conversion,
model semantics — remains upstream's and is documented in [the documentation map](README.md).

## Scope

`-DCMAKE_CUDA_ARCHITECTURES=89` builds the same engine for Ada. Supported SKUs share one cubin
because every capacity decision is read from the device:

| Card | SMs | L2 | Note |
|---|---:|---:|---|
| RTX 4090 | 128 | 72 MB | |
| RTX 4090D | 114 | 72 MB | China-market cut-down AD102 |
| RTX 4080 SUPER | 80 | 64 MB | also the 32 GB modified variants |
| RTX 4070 (Ti) / 4060 | 48–60 | 32–36 MB | smaller KV budgets, same binary |

Accepted inputs are the same v3 `.ninfer` artifacts upstream produces. A build selects exactly one
architecture, and the runtime refuses a device whose compute capability does not match what it was
compiled for (`src/models/qwen3_5/program/planning/startup.cpp`), because a cubin only loads on the
family it was generated for.

## What Ada does not support, and why

FP4 and the instruction encodings that carry it exist only on Blackwell, so the Ada build does not
compile them and answers with an explicit error instead of a degraded approximation:

| Feature | Ada status | Reason |
|---|---|---|
| `nvfp4` weight artifacts | unsupported | `mma ... scale::: block-scaled FP4`, `cvt.rn.satfinite.e2m1x2.f32` |
| NVFP4 / K8V4 KV cache | unsupported | same FP4 codec in the append and attention kernels |
| TMA-fed warp-specialized kernels | unsupported | `cp.async.bulk.tensor`, `setmaxnreg` (sm_90+) |
| Programmatic dependent launch | replaced by a stream-ordered launch | `griddepcontrol` (sm_90+) |
| Everything else (groupwise-int weights, FP8/BF16 routes, MTP/DFlash/DFlash2, INT8/FP8 KV, the Ada-only `rk4v4-e8` E8 lattice KV route, static YaRN context extension, vision, serving) | supported | |

The dropped translation units and their stubs are listed in
[`cmake/Sm89Compat.cmake`](../cmake/Sm89Compat.cmake); the error text each stub raises names the
artifact recipe to use instead. The split is mirror-symmetric: the `sm_120a` build drops
the Ada-only `rk4v4-e8` append/attention translation units the same way
([`cmake/Sm120Compat.cmake`](../cmake/Sm120Compat.cmake)) and answers the route with an
explicit status, because Blackwell ships native NVFP4 KV and does not need the E8 route.

## The four architecture deltas

Enumerated by compiling every CUDA translation unit of upstream `master` for `sm_89` and classifying
the failures: 39 of 185 units fail, in four root causes. The same set is what the community Ada
ports had to solve, in a different file layout.

1. **FP8 MMA encoding** — `src/ops/common/mma.cuh`. Blackwell spells the FP8 tensor-core
   instruction `mma.sync.aligned.kind::f8f6f4.m16n8k32.row.col.f32.e4m3.e4m3.f32`; Ada exposes the
   same m16n8k32 e4m3 operation without the `.kind::` selector, with identical fragment layouts. One
   architecture-conditional string keeps 12 FP8 A8/A16 translation units on tensor cores rather than
   falling back to slower SIMT paths.

2. **Shared-memory budget** — the `q8` GEMM families declared staging unions up to 99 KB statically,
   which Blackwell permits and Ada does not (48 KB per block). Rather than retune the tiles — which
   would change K-split reduction order and therefore the numbers — the affected routes now take the
   *same* layout from the dynamic window, exactly as the BF16 and FP8 launchers already do with the
   project's `> 48 * 1024` convention. `Q8*SharedWindow` is the single source of truth for the size,
   shared by the kernel and its 23 launchers. Ada's 99 KB dynamic ceiling covers every instantiation
   in the tree. See `src/core/shared_window.cuh`.

3. **Programmatic dependent launch** — `src/core/pdl.cuh`. On Ada the dependent launch degrades to a
   plain stream-ordered launch, and the producer/consumer hooks become no-ops: stream ordering
   already guarantees the producer finished, so correctness is unchanged and only the overlap is
   lost. Four translation units that had inlined `griddepcontrol` through this header compile again.

4. **Blackwell-only kernel routes** — dropped from the archives and replaced by
   `src/ops/sm89/nvfp4_sm89_stubs.cpp`. The `Nvfp4LinearShape` objects are still defined, with their
   real `n`/`k`, so shape resolution and workspace sizing keep working; only the kernel entry points
   raise, and `uses_a4` reports false so planning never selects the FP4 route on Ada.

One further change is not a compile failure but a hard block at startup: upstream's model runtime
required compute capability 12.0. It now requires the capability the binary was compiled for.

## Build and dependencies

The Ada build needs **CUDA 12.8 or newer**: the FP4 decode paths that remain useful on Ada include
`<cuda_fp4.h>`, which the toolkit ships only from 12.8. CMake enforces that floor rather than letting
a 12.6 host drown in missing-header errors. Verified on 12.8.93 and 13.2.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=89
cmake --build build -j            # libraries, CLI, server
cmake --build build --target ninfer-link-smoke -j
```

Upstream requires the FFmpeg development packages unconditionally at configure time; the only
consumer is the media decoder, so `-DNINFER_ENABLE_VISION=OFF` links a stand-in and lets a text-only
build succeed with just the CUDA toolkit. Requests that carry image or video input then fail with a
message naming the option. `libcurl >= 7.85` is still required for the server and any build with
`NINFER_BUILD_APPS=ON` (Ubuntu 24.04 or newer, or the container below).

For a reproducible toolchain, the container recipe parameterizes both architecture and CUDA version:

```bash
docker build -f Dockerfile.sm89 --build-arg CUDA_IMAGE=nvidia/cuda:12.8.1-devel-ubuntu24.04 -t ninfer-ada .
```

## Verification

Measured on an **RTX 4080 SUPER (32 GB, sm_89), CUDA 12.8.93, host GCC 11.4, Ubuntu 22.04**,
from this exact tree at the `sm_89` architecture, unless noted.

| Claim | Evidence | Result |
|---|---|---|
| `sm_89` configures, compiles, links | full tree + `NINFER_BUILD_APPS=ON` + tests | green, 0 errors |
| `sm_120a` path is bit-for-bit upstream on the shared-memory request | `Q8KSplitAdaSharedWindow` returns 0 off Ada; launchers that passed a literal 0 upstream still do | verified by construction |
| Op suites pass on Ada silicon | `ctest` over the whole registered suite | **110 / 110 passed**, the 10 Blackwell-only cases correctly disabled, 0 failures |
| v3 `groupwise-int` artifact loads and runs | official upstream artifact + both ModelScope artifacts (`QilinWan`/`mrwan0410`) | text, MTP, DFlash2, vision all working |

| Cooperative GDN gating is correctly sized | a `sm_120a`-constant grid raised `cudaErrorCooperativeLaunchTooLarge`; after the Ada residency measurement it passes | fixed, `cuobjdump`-backed |
| Chat template and tokenizer are in the artifact | v3 manifest `text.resources.{tokenizer.json,chat_template.jinja,…}`, no external mmproj file | confirmed by parsing the container |

### Measured throughput

Tuned 2026-09-24 on the same RTX 4080 SUPER 32 GB card with two Qwen3.8-27B `groupwise-int`
artifacts carrying an MTP head (`…-mtp`) and a DFlash2 head (`…-df2`). Greedy, INT8 group-64 KV,
`--prefill-chunk 2048`, one lane, 512 new tokens unless noted; decode is the phase rate excluding
prefill. Raw logs and one-click scripts live with the report (`mtp-best.sh` / `df2-best.sh`).

| Artifact | Best spec setting | Code | Structured | Math | Narrative | No-spec |
|---|---|---:|---:|---:|---:|---:|
| `…-mtp` | `--spec mtp --draft-tokens 3 --lm-head-draft` | 88.1 | 111.2 | 101.3 | **75.2** | 40.1 |
| `…-df2` | `--spec dflash2 --draft-tokens 7 --lm-head-draft` | **100.9** | **149.6** | **116.8** | 64.5 | 40.1 |

Rates are tok/s. K-sweep (four-scenario means): MTP K=2/3/4/5 = 80.5 / **91.4** / 84.4 / 84.0
(the head is trained for a 3-token window, K=6 is rejected); DFlash2 K=3/5/7/9 = 93.4 / 98.5 /
**101.0** / 81.6, with a cliff past K=9. At 1024-token generations K=5 (97.7) overtakes K=7 (90.3),
so prefer K=5 when long-output stability matters. `--lm-head-draft` is a win on both heads on Ada
(+9% MTP, +5-11% DFlash2; the earlier untuned note that it slowed DFlash2 did not reproduce).
KV dtype: INT8 optimal (fp8 -2~-10%, NVFP4/K8V4 refused on Ada by construction, see the route
error above). `--no-thinking` adds ~16% on either head. Prefill is 1.45-1.52k tok/s at 6.8K prompt
across chunks 512-4096.

Serving at 262,144 tokens/sequence, shared 262,144-token INT8 pool: KV payload 8.77 GiB (MTP) /
8.25 GiB (DFlash2); C=1/2/4 = 80.2/121.8/142.8 (MTP) and 85.3/109.2/159.1 (DFlash2) aggregate
tok/s, with 1.76 GiB VRAM headroom at C=4. C=8 at full context fails the startup reservation
(needs ~17.1 GiB after weights, ~13.6 available). Quality spot-checks: INT8-vs-BF16 PPL delta
+0.025% on a 15.8K-token English sample; speculative output byte-identical to no-spec across 5 runs.

Multimodal path: `--vision` + an image message decoded a PNG chart (after the FFmpeg-6 note below),
answered its title/values, and stopped on the stop-token (`finish reason stop-token`); video input
expands to ~1.2K prompt tokens at 67 ms vision encode with no decode-speed impact.

### Environment notes found while verifying (each one bites a fresh sm_89 machine)

* **FFmpeg ≥ 6 is required by `NINFER_ENABLE_VISION=ON`, and Ubuntu 22.04 ships FFmpeg 4/5**
  (`libavcodec 58`); the code needs the FFmpeg-6 `av_packet_side_data_get`. CMake now fails at
  configure time with the version it found and points at `-DNINFER_ENABLE_VISION=OFF`.
* A self-built FFmpeg must keep **zlib** (PNG): `--disable-autodetect` silently drops it and image
  decode then fails as *"media codec is not supported"* even though everything compiled. Configure
  with autodetect on, or add `--enable-zlib`.
* The loader picks the **wrong `libstdc++`** when a conda/`/root/miniconda3` lib directory is on the
  path: the engine needs `GLIBCXX_3.4.30`, conda's copy predates it, and the result is a binary that
  links but dies at launch. Run against the system `libstdc++` (`LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libstdc++.so.6`)
  or build against a `libcurl` that does not drag conda's runtime libraries in.
* A **private FFmpeg prefix is not on the loader path**; `libswresample`/`libswscale` need
  `LD_LIBRARY_PATH`, or the engine binary fails with `error while loading shared libraries`.
* Ada **cooperative-launch residency is a per-architecture register fact**; see
  `cooperative_resident_ctas_per_sm` for the measured `sm_89` table and why an inflated constant
  aborts a prefill.

### Ada hardware acceptance checklist

Run on one Ada card, in this order, recording GPU name, driver, CUDA version and revision:

1. `ctest -R "fp8|q8|linear|gdn" --output-on-failure` (configure with `-DBUILD_TESTING=ON`): op
   routes against the FP32/FP64 oracles.
2. `./build/apps/ninfer models/qwen3_8_27b.ninfer --prompt "..." --max-tokens 64` with
   `--spec none`, then `--spec mtp --draft-tokens 3`: greedy prefix equality between the two, and
   between the `sm_120a` build and this one on the same artifact.
3. `--kv-cache int8` at `--max-context 262144` on a 32 GB card: startup capacity report and a long
   prompt round-trip.
4. `ninfer-perplexity` on the small held-out corpus: within upstream's published tolerance for the
   same artifact and recipe.
5. One decode and one prefill throughput sample per claimed SKU, written to
   `docs/performance/`.

## Provenance

Ada support never existed upstream, so the shape of the port had to come from the community lineage
that built it on pre-v3 baselines. Each of their solutions was re-derived against the current tree
rather than cherry-picked, because upstream renamed and restructured the files they patched
(`src/targets/ → src/models/`, the converter rewrite, the v3 loader and the bound-instance-parameter
engine):

| Contribution | Source |
|---|---|
| first Ada/`sm_86` runtime qualification of the Qwen3.8 27B target | `785d856b` in `Don-Chad/ninfer-3090` lineage |
| `sm_89` specialization: arch gate, `NINFER_SM89` define, PDL fallback, L2 persistence, W8 schedule selection | `a14d686c`, `2b5cd40a`, `ccb20680` in [`UDPSendToFailed/ninfer-4090`](https://github.com/UDPSendToFailed/ninfer-4090) |
| removing NVFP4 from an Ada build rather than faking it | `dabae909` in the same repository |
| device-derived SM count instead of a compile-time constant; DFlash2 on Ada | [`YurunTao/ninfer-4080S-32G`](https://github.com/YurunTao/ninfer-4080S-32G) |

The L2 persistence-window tuning from that lineage is deliberately **not** included: it is a
performance claim that needs measured A/B evidence on Ada hardware, and it is queued behind the
acceptance checklist above.

## Staying current with upstream

This repository is based on upstream `master` and keeps the Ada work in a small number of reviewable
layers: the architecture gate and route exclusions, the shared-memory window, the PDL fallback, the
FP8 encoding, and the capability check. That ordering is chosen so that upstream can be merged, not
replayed: when upstream refactors a file, the conflict is limited to an `#ifdef` or a window size
rather than a re-derivation of the port, which is what makes staying on v3 possible at all.

```bash
git fetch upstream && git merge upstream/master
cmake --build build-sm89  && cmake --build build-sm120a   # both must stay green
```

`cmake/Sm89Compat.cmake` excludes translation units by path pattern; a merge that renames one of them
surfaces as either a compile failure of an excluded Blackwell unit on `sm_89` or as an unresolved
symbol in `ninfer-link-smoke`. Both are checked in CI.
