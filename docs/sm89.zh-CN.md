# NInfer Ada（sm_89）移植说明（中文）

> 本页是英文权威文档 [docs/sm89.md](sm89.md) 的中文镜像；两者以英文版为准，
> 中文版同步到同一提交。产品行为（CLI、HTTP 服务、权重转换、模型语义）仍属上游，见
> [文档地图](README.md)。

本仓库在上游 [Neroued/ninfer](https://github.com/Neroued/ninfer)（只编译 `sm_120a`，即 RTX 5090）
之上，新增一套 **Ada（`sm_89`）** 构建：RTX 4090 / 4090D / 4080（SUPER）/ 4070（Ti）/ 4060。
**同一份代码、同一套 v3 `.ninfer` 权重、同一种对话质量**，也能跑在保有量最大的这代消费卡上。

## 一句话结论

上游把权重容器从 v2 换成 v3 时，**只改了容器与清单，量化后的权重字节没变**
（上游自带的 `tools/upgrade_ninfer_v2_to_v3.py` 就是"重新打包、不重量化"的活证据）。
因此我们**以 `master` 为基座**，而不是以某个 v2 时代的老分叉为基座：这样吃 v3 是白送的，
上游继续演进时用 `git merge` 跟进即可，而不是每次重写一遍移植。

## 支持矩阵

| | Ada（`-DCMAKE_CUDA_ARCHITECTURES=89`） | Blackwell（`120a`，上游默认） |
|---|---|---|
| 权重容器 | **仅 v3** | 仅 v3 |
| 权重档 | `groupwise-int`（Q4/Q5/Q6/Q8 + Q8 词表） | groupwise-int、`nvfp4` |
| 投机解码 | MTP、DFlash、DFlash2 | 同左 |
| KV 缓存 | INT8、FP8、BF16 | 外加 NVFP4、K8V4 |
| 多模态（图/视频） | 支持，需 FFmpeg ≥ 6（见下） | 同左 |
| CLI / HTTP 服务 | 支持 | 支持 |

一份 cubin 覆盖整个 Ada 家族：SM 数、L2 大小、常驻度全部**运行期从设备读取**，
所以 4090（128 SM）、4090D（114 SM）、4080 SUPER（80 SM）共用同一二进制。

## 快速构建

```bash
git clone https://github.com/QilinWan/Ninfer-Blackwell-Ada.git && cd Ninfer-Blackwell-Ada

# Ada（RTX 40 系）
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=89
cmake --build build -j

# Blackwell（RTX 5090）：与上游完全一致
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=120a
cmake --build build -j
```

依赖：64 位 Linux、CMake ≥ 3.28、C++20、Ninja/Make、CUDA 工具链、`pkg-config`；
开 `NINFER_BUILD_APPS=ON`（CLI/服务）还需 `libcurl ≥ 7.85`；开视觉需 FFmpeg ≥ 6 开发库。
纯文本构建可用 `-DNINFER_ENABLE_VISION=OFF` 免掉 FFmpeg 依赖。

## 踩过的坑（每个都会咬一台新 Ada 机器）

1. **FFmpeg 版本地板**：视觉解码用的是 FFmpeg 6 的 `av_packet_side_data_get`；
   Ubuntu 22.04 只有 `libavcodec 58`，会在 `decode.cpp` 深处编译失败。我们把检查提前到配置期，
   报错会直接告诉你装到的版本，并指向 `-DNINFER_ENABLE_VISION=OFF`。
2. **自编译 FFmpeg 别丢 zlib**：`--disable-autodetect` 会顺手关掉 zlib，PNG 解码器随之失效，
   即使全部编译通过，图像输入仍会报 *"media codec is not supported"*。保持 autodetect 开启，
   或显式 `--enable-zlib`。
3. **`libstdc++` 抢库**：当 `/root/miniconda3/lib` 之类目录在库搜索路径里时，链接器塞进来的 conda
   `libstdc++` 版本偏旧、缺 `GLIBCXX_3.4.30`，二进制能编出来但一启动就死。用系统的
   `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libstdc++.so.6`，或换一个不牵连 conda 运行时的 `libcurl`。
4. **私有 FFmpeg 前缀不在加载路径**：自装的 `libswresample/libswscale` 需要
   `LD_LIBRARY_PATH=<prefix>/lib`，否则 `error while loading shared libraries`。
5. **`libcurl ≥ 7.85`**：Ubuntu 22.04 自带 7.81，开 apps 会卡在配置期；用 24.04+ 或自带一份 curl。
6. **Ada 协同启动常驻度是"每架构寄存器事实"**：GDN 门控投影的 cooperative 网格预算在 Ada 上更小
   （见 `cooperative_resident_ctas_per_sm`），沿用 sm_120a 常数会 `cudaErrorCooperativeLaunchTooLarge`。
7. **`--thinking-budget` 与 `--max-new`**：思考预算太接近输出上限会报"闭合控制后缀放不下"，
   给 post-close 至少留一个 token。

## 权重从哪来

不需要为 Ada 单独准备权重。两种途径：

* 直接下载官方/社区 **v3 `groupwise-int`** 产物（`model-cards/` 与各模型卡有链接）；
* 用上游 `tools/convert`（离线转换）或 `tools/upgrade_ninfer_v2_to_v3.py`（把已有 v2 重新打包成 v3，
  不重量化、不重新下载）。

## 启动与多模态

视觉投影器**打包在 `.ninfer` 容器内**，没有独立 mmproj 文件；未选中的组件不占显存。
读一下自己产物的 v3 清单即可确认它含哪些组件（`components`：`text` / `vision` / `mtp`|`dflash2`）：

```bash
# 文本 + MTP
./build/apps/ninfer model.ninfer --prompt "……" \
  --max-context 262144 --kv-dtype int8 --spec mtp --draft-tokens 3 --lm-head-draft --vision

# 文本 + DFlash2（该档一般不加 --lm-head-draft，Ada 上更慢）
./build/apps/ninfer model.ninfer --messages messages.json \
  --max-context 262144 --kv-dtype int8 --spec dflash2 --draft-tokens 7 --vision
```

## 实测吞吐（功能验证级，未调优）

同题、131072 上下文、INT8 group-64 KV、`--prefill-chunk 2048`、512 新 token、单并发，一次采样：

| 产物 | 投机 | 解码 | 预填充 | 接受率 |
|---|---|---:|---:|---|
| `…-mtp` | MTP, draft 3 + lm-head | 80.6 tok/s | 627 tok/s | 49.9%、2.49 tok/轮 |
| `…-df2` | DFlash2, draft 7 | 83.0 tok/s | 630–642 tok/s | 36.0%、3.49 tok/轮 |

多模态：`--vision` + 图像 message 成功解码一张 PNG 图表、读出标题与计数、正常 `stop-token` 结束。

## 验证状态

在 **RTX 4080 SUPER（32 GB，sm_89）、CUDA 12.8.93、GCC 11.4、Ubuntu 22.04** 上：
全量 `ctest` **110 / 110 通过**，10 个 Blackwell-only 用例按架构正确禁用、0 失败；
`sm_120a` 与 `sm_89` 两份树都干净编译+链接。逐项证据见英文 [docs/sm89.md](sm89.md#verification)。
