# 本版本的两项核心能力：sm_89 的 4-bit KV，与全系上下文外推

> 面向 RTX 40 系（Ada / sm_89）与 RTX 50 系（Blackwell / sm_120a）双架构。
> 所有数字均为**实测**，非推算；测量环境与复现方式见文末。

---

## 一、我们在 sm_89（Ada / RTX 4080S）上实现了 4-bit KV

这是本版本最重要的能力：**Ada 架构此前没有可用的 4-bit KV 路线**。
我们新增了 **`rk4v4-e8`** —— 基于 **E8 Conway–Sloane 格点**的 K/V 双 4-bit 压缩：

| 项目 | 数值 |
| --- | --- |
| K 编码 | D256 Hadamard 旋转（×1/16）→ 8 维子空间 E8 格点投影 → `rintf` 截断 [-8,7] |
| V 编码 | 同一旋转 → `__float2int_rn` 截断 [-7,7] |
| 每 token 每 kv head | **130 字节**（128 字节码 + 2 字节 K 标度 + …）|
| 相比 int8 KV | **约 2.5 倍压缩** |
| 解码 | 4-bit 码解包为 int8 → s8 张量核 QK + FP16 PV（零额外反量化开销）|

**实测（32 GB Ada 卡 + 27B 产物）**：文本生成正确、多模态读图正确、
DFlash2 接受率 **36.1% / 41.8%**、decode **83.4 / 91.5 tok/s**；
MTP 接受率 **63.2% / 66.7%**、decode **81.8 / 83.0 tok/s**。

> 同一张卡上的 `nvfp4` / `k8v4` 是**刻意不可用**的：它们需要 Blackwell 的 FP4 转换、
> 块缩放 MMA 与 TMA，`src/ops/sm89/nvfp4_sm89_stubs.cpp` 会直接报错而不是算出错误结果。

## 二、全系上下文外推（YaRN），sm_89 与 sm_120a 双架构支持

静态 YaRN 在本版本**同时覆盖两代架构**：`--rope-yarn-factor F`（1~4）配合
`--rope-original-max-position 262144`，把可用窗口扩大到原生窗口的 F 倍。

**关键工程点**：位置上限、注意力包络与草稿窗口**三者全部跟随因子缩放**，
而切分几何本就随 `max_visible_keys` 增长——因此**无需改动任何内核即可外推**。

### 实测上下文上限（均为 32 GB 卡）

| 配置 | **sm_89 / Ada（`rk4v4-e8`）** | **sm_120a / 5090（`nvfp4`）** |
| --- | --- | --- |
| 裸跑（无多模态、无投机）| **约 820,000 token** | **约 790,000 token** |
| + 多模态 | 约 720,000 token | 约 730,000 token |
| + 多模态 + 投机 + 2 并发 + 全调优 | **512,000 已验证可用**（上限约 544K）| **580,000 实测可用** |
| 1,048,576（1M）| ❌ 需约 34.7 GiB | ❌ 需约 34.7 GiB |

**1M 不可行的原因是显存预算**（引擎明确报 `minimum Engine runtime reservation requires …`），
**不是软件限制**；需要 48 GB 级显卡。若把 KV 压到 3-bit 才可能挤进 32 GB。

## 三、r2 修复了什么（相对 r1）

r1 的 `rk4v4-e8` 会输出**看似流畅的乱码**。根因不是编码，而是
**注意力输出缺少逆旋转**：

```
V 存的是 H·V  ⇒  O = Σpⱼ(H·vⱼ) = H·O_true  ⇒  必须再乘 H⁻¹ = H
```

存储、寻址、编码、标度、解码**全部正确**，唯独最后一步输出没转回来。
r2 另修复三处：融合追加前发布页表（竞态→非法访存）、批量启动器分发 `RK4V4E8`
（原先落进 BF16 内核导致越界写）、小 T arena 四区重叠。

**建议使用 r2 及以上版本，不要用 r1 的 E8 路线。**

---

## 四、一个已知限制：`nf4` 产物上 DFlash2 不可用

```
FATAL | linear_topk: unsupported head profile
```

DFlash2 草稿的候选选择器 `linear_topk` 只接受 `Q8_G32_FP16` /
`FP8_E4M3FN_ROW_BF16` / `Q4_G64_FP16` 三种格式，而 `nf4` 产物把该选择器头
也量化成了 NVFP4。**这是权重转换疏漏，不是引擎缺陷**——目标权重以 NVFP4
正常加载。**MTP 不受影响。**
